# V2 2.0.4: Pix e recebimento em duas etapas

## Comportamento

- Motoboy acessa Meu Pix pelo avatar ou botão acima das telas. Cadastra tipo, chave e titular. E-mail e chave aleatória preservam o formato técnico, sem conversão visual forçada para maiúsculas.
- Backend valida formato e autoria. CPF/CNPJ têm validação de formato e quantidade de dígitos, sem consulta bancária ou comprovação de titularidade.
- Ao concluir a corrida, a chave é copiada para o pedido privado da loja e do motoboy. Cadastro posterior atualiza pedidos concluídos ainda pendentes.
- Loja vê valor, titular e botão Copiar chave Pix. O aplicativo não movimenta dinheiro.
- Somente a loja dona informa pagamento: `pending` → `reported`, com autor e horário. `paid` continua falso.
- Somente o motoboy responsável confirma depois da informação da loja: `reported` → `confirmed`. Autor e horário próprios são preservados, e `paid` passa a verdadeiro.
- Informar pagamento e confirmar recebimento têm confirmação na interface. O backend também exige as duas etapas e entrega concluída.
- Repetições não duplicam evento ou atualização push. O admin não substitui as partes nessa confirmação.
- A chave registrada em pagamento já informado ou confirmado não muda quando o motoboy altera o cadastro. Ela documenta os dados apresentados no aplicativo, sem comprovar qual chave foi usada no banco.
- Pagamentos antigos com `paid: true` permanecem no histórico, sem inventar segunda confirmação nem apagar autoria anterior. Pendências antigas passam pelo novo fluxo sem necessidade de reimportar o banco.
- O comando legado `toggle-pay` passa a respeitar o papel autenticado: loja informa, motoboy confirma apenas após informação. APK antigo não pode mais quitar pelo lado da loja, embora seu texto de confirmação possa ficar desatualizado. Atualizar ambos os perfis para 2.0.4.

## Dashboard e pendências

Relatório acumula entregas concluídas, valor das entregas, recebido/confirmado, a receber/acertar, pagamentos informados e pendências de dias anteriores. Valores informados não entram como recebidos.

Pendências agrupadas por data de conclusão e contraparte: lojista para o motoboy, motoboy para o lojista. A comparação dos dias usa `America/Sao_Paulo`, inclusive na virada da meia-noite. Histórico recebido é separado das pendências. O aplicativo recalcula a classificação por dia enquanto as telas de relatórios/concluídos estão abertas.

Motoboy vê aviso persistente de pagamentos para conferir e recebe aviso não bloqueante após aceitar outra corrida. Loja vê pendências de dias anteriores e acesso ao relatório. Nenhuma pendência financeira interfere no limite operacional de duas vagas ou na disponibilidade.

Não há multa, juros, bloqueio, transferência automática, confirmação bancária, pagamento parcial ou baixa em lote nesta etapa. Lembretes financeiros desta entrega são visuais no aplicativo; não foi criado cron de cobrança diária.

## Privacidade

Pix permanece em `profiles/couriers/UID/pix` e no campo `paymentPix` dos pedidos privados. Não entra em murais, rastreio público ou payload de push. As regras publicadas já impedem leitura de perfil alheio e escrita direta em perfil/pagamento, portanto não é necessário abrir caminhos nem publicar novas regras.

## Ativação no ambiente de testes

Atualizar código e instalar o APK 2.0.4 não atualiza sozinho o servidor. A nova lógica precisa de publicação das funções em `express-entregas-2-testes`.

No Cloud Shell, dentro de uma cópia atualizada da branch `v2.0-testes-reais`, preservando o arquivo local `functions/.env.express-entregas-2-testes`:

```sh
npm ci
npm ci --prefix functions
node scripts/deploy-payments-v2.mjs
```

O script publica somente as quatro funções conhecidas, usa explicitamente o projeto de testes e não importa dados, não muda regras, não ativa cobrança e não publica site. Segredo VAPID existente permanece no Secret Manager. Não gerar outro par de chaves.

Para a pasta `express-v2.*` já utilizada no Cloud Shell, esta linha baixa o código exato validado dentro da mesma pasta, preservando o arquivo local de ambiente. Se houver mais de uma pasta compatível, `cd` interrompe a execução para não escolher silenciosamente outra cópia:

```sh
cd "$HOME"/express-v2.*/ && curl -fL https://github.com/fmrpbr/Express/archive/d20a29f83ecdb590082b21eed35f8d30e11ffecd.tar.gz -o /tmp/express-pix-204.tar.gz && tar -xzf /tmp/express-pix-204.tar.gz --strip-components=1 && npm ci && npm ci --prefix functions && node scripts/deploy-payments-v2.mjs
```

Depois, instalar o APK e usar duas contas para cadastro Pix → concluir entrega → copiar chave → informar pagamento → conferir conta bancária → confirmar recebimento. Pagamentos dessa conferência devem ser registros de teste. Só considerar a etapa ativa após evidência do deploy. Aprovação do piloto continua separada.
